# Website quality and dependency maintenance

Run `npm ci` and `npm run build`, then `npm run check:accessibility` and `npm run check:lighthouse`. Both commands use an already installed Chrome browser; set `CHROME_PATH` if it is outside the standard locations. They serve the built site on loopback and never upload reports to a public report service.

The accessibility check covers the V38 front door, preserved V37 homepage, and cAshIo introduction at 1440, 390, and 320 pixels. It fails on serious/critical axe findings, horizontal overflow, JavaScript runtime errors, or audible startup media. Moderate/minor findings and rules needing human review remain visible in the JSON report. Reduced motion is enabled for these scans. Existing runtime checks and manual keyboard, screen-reader, visual, and device reviews remain necessary.

Lighthouse CI runs three mobile lab measurements per route. Accessibility and best-practice thresholds block failures; performance and SEO thresholds initially warn because lab results vary by runner and private previews can intentionally discourage indexing. Reports and screenshots are written to `artifacts/quality/`. These are lab measurements, not real-user Core Web Vitals.

The Lighthouse wrapper lets Playwright own a temporary Chrome profile and graceful shutdown, avoiding the Windows profile-deletion race in chrome-launcher. Lighthouse connects through a temporary loopback debugging port. Chrome keeps its sandbox enabled and uses the Linux runner's configured sandbox helper. No existing browser profile is opened. The report-collection steps continue after a failure so artifacts can be saved; the final validation gate checks their raw outcomes and rejects any failure.

Renovate proposes updates with manual dashboard approval and automerge disabled. Regular updates are grouped and scheduled before 7:00 AM on Mondays in America/Chicago, with a seven-day release age and at most two concurrent regular PRs. Security update handling can bypass ordinary limits. Review update notes and the quality results before merging.

Use Node.js 24 for local checks, matching CI. Lighthouse CI 0.15.1 uses an explicit Lighthouse 13.5.0 override to replace its vulnerable browser-download dependency tree. The checks use installed Chrome and do not download a browser. Remove this override only when the upstream CLI includes a patched Lighthouse and collection, assertions, and filesystem reports pass with the replacement. Compatible patches remain pinned for `tmp`, `qs`, and `uuid`. Recheck `npm audit` and the browser gates whenever updating these tools.

GitHub Actions are pinned to reviewed commit digests. Checkout credentials are not retained, and publishing workflows do not reuse dependency caches. Install the workflow scanner with `python -m pip install --no-deps --require-hashes -r requirements-workflow-security.txt`, then run `npm run check:workflow-security`. This offline check requires the exact pinned scanner version and fails if scanning is incomplete or reports a finding. Its sanitized report is saved under `artifacts/quality/workflow-security.json`. Renovate maintains action digests and the scanner requirements alongside npm dependencies, with the same manual approval and no-automerge policy.

Compatible updates can be tested together. Major toolchain migrations, including Vite and TypeScript, require a separate compatibility review; a clean audit does not mean every package is on its newest major release.
